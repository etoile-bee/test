LE SYSTÈME VIVANT — vue dynamique du modèle (avant toute forme)

Statut : ANALYSE — vue du fonctionnement, pas une représentation. On décrit comment le modèle vit
: comment les 24 objets, leurs états, relations, cycles de vie, décisions et les **15
invariants se matérialisent dans le comportement du système. Zéro vocabulaire de forme** (aucune
notion de support, de présentation ni de manipulation concrète). Live intact · fichiers verrouillés
intacts · aucune dépense.
Ancrage E127 : ① Intention · ② Cohérence · ③ Mémoire · ④ Capitalisation · ⑤ Confiance · ⑥ Contrôle.
Phrase centrale : « Je pilote la transformation d'une intention en contenu publiable, par une suite de
décisions cohérentes, réversibles et mémorisées, dans un système en qui j'ai confiance — jusqu'au seul
acte définitif : publier. »
Rappel taxonomie : objet (niveau 1) · état (niveau 2) · composante/attribut (niveau 3) ·
rôle dérivé/vue (niveau 4). Le Média produit est un objet à états ; le Média actif est un
rôle.

1. COMMENT UN PROJET NAÎT

Un Projet ne surgit pas de rien : il descend de l'Univers.

  • Point de départ — l'Univers. Le monde (Univers) détient déjà les bibliothèques, les règles

éditoriales/visuelles et les lignes de publication. À la création d'un projet, ces valeurs utiles sont

copiées au point d'entrée dans le projet (M12) : à partir de là, le projet est autonome.

Modifier ensuite l'Univers ne touchera jamais ce projet (étanchéité, INV-11).

  • La boussole d'abord — l'Intention. Le projet naît porteur d'une Intention composite : ses quatre

composantes — Message · Émotion · Public · Objectif (plateforme/format/durée) — sont **définies ou

esquissées**. Esquissée suffit pour démarrer ; elle restera modifiable. Sans intention, le système ne

peut pas poser sa question centrale.

  • Qui incarne — le Personnage employé. Le projet emploie un Personnage de l'Univers ; ses

Référence, Look (garde-robe) et Voix-signature utiles sont copiés comme **instances

appliquées** (étanches), jamais empruntés en lien vivant (M23/M12).

  • État initial. Le projet est brouillon, sa mémoire (Décisions, Historique) est vide, aucun **Média

produit** n'existe encore.

Comportement clé : naître = hériter d'un cadre par copie, puis devenir indépendant. Le monde donne un
point de départ ; le projet en devient le seul propriétaire.

2. COMMENT UN PROJET ÉVOLUE

L'évolution n'est pas linéaire : c'est une suite d'allers-retours maîtrisés.

  • Production de matière. À partir des consignes et des créatifs, le système produit des **Médias

produits**. Chaque média naît à l'état candidate (non jugé).

  • Transitions d'états du Média produit (un seul objet, plusieurs états) : candidate → variante

(alternative conservée) → désigné média actif (rôle exclusif : la source courante) → écartée

(réversible) → retenue-pour-livrable. Aucune duplication : le même média change d'état.

  • Chaîne non-linéaire. On peut revenir en arrière à tout moment : changer un Look, réécrire un Script,

régénérer un média, restaurer une Version antérieure, réactiver une variante écartée. Rien n'est

perdu (INV-6/INV-8).

  • Ré-éditabilité jusqu'à la publication. Tant que rien n'est publié, **toute orientation reste

défaisable**. La seule frontière irréversible est la Publication (INV-7).

  • Versions : à des moments choisis, le système fige un instantané restaurable (Version) — un point

de retour qui n'efface aucun autre.

Comportement clé : avancer sans jamais se fermer de porte — la production est un espace réversible
jusqu'au dernier acte.

3. COMMENT LES OBJETS INTERAGISSENT (les 24 en mouvement)

Qui déclenche quoi, qui produit quoi :

  • Univers alimente (par copie) Bibliothèque → Briques, Personnage, Série, et les règles

qui cadrent les projets.

  • Intention oriente tout : elle est la référence de la cohérence et le sens des décisions.
  • Personnage fournit Référence / Look / Voix (copiés en instances).
  • Consigne + Look/Décor/Ambiance + Référence → produisent des Médias produits (états successifs).
  • Script → interprété par la Voix ; Médias produits retenus → assemblés par le Montage

(rythme en attribut).

  • Contrôle qualité s'intercale avant toute production coûteuse : il juge l'aptitude technique

d'un média.

  • Coût (attribut) accompagne chaque production : estimé avant, réel après.
  • Une Version validée → engendre un Livrable (paquet : média final + Légende + Hashtags +

Paramètres + RAW…).

  • Un Livrable → alimente une Publication.
  • Chaque choix structurant → engendre une Décision ; toutes les Décisions → nourrissent l'Historique

(vue dérivée).

  • L'Évaluation de cohérence (vue dérivée) lit en continu l'écart entre les pièces produites et

l'Intention.

Comportement clé : un flux orienté par l'intention où chaque objet a un déclencheur clair et un
produit clair — pas de zone grise de propriété.

4. COMMENT LES DÉCISIONS SE PROPAGENT

  • Une action structurante = une Décision (M16) — porteuse de sa raison (obligatoire pour les choix

majeurs : rejet, abandon de direction, remplacement majeur, validation de livrable, publication ;

proposée sinon — M13).

  • Les conséquences automatiques ne sont pas des décisions : valider un livrable est une décision ;

la version retenue qui se fige en est une conséquence, pas une seconde décision.

  • Impact aval, au choix, jamais en silence. Quand une modification amont peut affecter l'aval déjà

produit, le système n'efface rien automatiquement : il expose le choix — garder l'aval,

mettre à jour, ou régénérer — et attend la décision de la personne (INV-6, ⑥/⑤).

  • Superséder sans effacer. Revenir sur un choix ne réécrit pas le passé : une nouvelle Décision

supersède l'ancienne, qui reste dans la mémoire (INV-5). On lit toujours la chaîne complète.

  • Décision incomplète. Une décision structurante posée sans raison est **tracée mais marquée

incomplète** (M17) : la trace n'est jamais perdue, la raison s'ajoute plus tard.

Comportement clé : chaque inflexion du projet laisse une trace expliquée, et **aucun effet n'est subi
en silence**.

5. COMMENT LA MÉMOIRE SE CONSTRUIT

  • Chaque Décision (action + raison + éventuelles annotations datées) s'inscrit dans l'Historique

(vue dérivée chronologique).

  • La mémoire conserve le pourquoi, pas seulement le quoi : variantes essayées, choix faits et leurs

raisons, écarts assumés, version retenue (+ sa raison de retenue).

  • Rien n'est effacé : écarter/archiver ≠ supprimer (INV-8) ; RAW, Versions, Décisions, Publications

sont permanents (INV-5).

  • Relisible des mois après : dérouler l'Historique reconstitue le raisonnement complet — *intention →

essais → choix + raisons → écarts assumés → version retenue → publication*.

  • Identités stables (M18) : les objets de mémoire gardent leurs identifiants à travers toute migration,

donc les références croisées restent valides indéfiniment.

Comportement clé : le projet se raconte lui-même ; on peut toujours comprendre *pourquoi il est ce
qu'il est*.

6. COMMENT LA CAPITALISATION FONCTIONNE

  • Promotion. Un acquis (un Look, un Décor, une Ambiance, une Consigne, des réglages = Preset, un

enchaînement de montage) peut être promu en brique-modèle dans la Bibliothèque (de l'Univers)

ou la garde-robe (du Personnage).

  • Provenance tracée. Chaque brique garde l'origine d'où elle vient (mémoire, ③).
  • Réutilisation par copie explicite. Employer une brique dans un projet en crée une **instance

appliquée (copie, niveau 3), étanche** : la modifier dans le projet ne touche pas la brique-modèle,

et inversement (M23/M12, INV-11).

  • Confusion impossible : la ressource réutilisable (modèle) et son emploi (instance) portent des noms

distincts.

Comportement clé : réutiliser, c'est copier — jamais hériter d'un lien vivant. Le capital grandit
sans contaminer les projets passés.

7. COMMENT LA COHÉRENCE EST ÉVALUÉE

  • Le système pose en permanence la question centrale : « **ce qui est produit sert-il encore

l'intention ?** ».

  • L'Évaluation de cohérence (vue dérivée) lit, pièce par pièce parmi les dix —

message · image · look · décor · voix · script · montage · rythme · légende · publication — si chacune

est alignée, à vérifier, non définie ou écart assumé, avec le pourquoi de chaque signal.

  • Elle localise la dérive (quelle pièce s'écarte) et la rend visible ; elle ne juge pas le goût

(aucun « beau/laid »), seulement la cohérence explicable.

  • Elle ne décide JAMAIS. La personne tranche : corriger la pièce, ou assumer l'écart. **Un écart

assumé est une Décision** (tracée, avec sa raison) qui « referme » le signal.

Comportement clé : un miroir, pas un juge — le système éclaire l'alignement, l'humain décide.

8. COMMENT LA PUBLICATION INTERVIENT

  • La publication ne sort pas d'un média isolé : elle part d'une Version validée → qui constitue un

Livrable (paquet autonome et complet) → dont l'état devient prêt-à-poster.

  • La Publication est le seul acte irréversible du système. Son effet est annoncé avant d'agir

(INV-12) ; une fois posé, la version publiée est figée et conservée en mémoire.

  • Avant cet acte, tout restait réversible ; après, seule la trace demeure (permanente).
Comportement clé : une seule porte sans retour, clairement annoncée — tout le reste lui est réversible
jusqu'au bout.

10. SCÉNARIO DÉROULÉ DE BOUT EN BOUT (idée → publication)

Un exemple concret de la vie d'un projet, montrant objets / états / décisions / mémoire / cohérence en
action. (Aucune notion de forme.)

1. Naissance. Dans l'Univers « Imany », une personne ouvre un Projet. Les règles visuelles et la

ligne de publication de l'Univers y sont copiées (M12). L'Intention est esquissée : Message =

« se sentir puissante au réveil », Émotion = douceur affirmée, Public = femmes 25-40, Objectif =

format court 9:16, ~23 s. Le Personnage Imany est employé ; sa Référence et un Look de la

garde-robe sont copiés en instances appliquées. (États : Projet brouillon.)

2. Production. À partir de la Consigne + Look + Décor « studio » + Ambiance « lumière

chaude », le système produit trois Médias produits, tous à l'état candidate. Le Coût réel est

relevé.

3. Premiers jugements. La personne examine : elle conserve B et C comme variante (deux

Décisions, raisons proposées : « B plus douce », « C plus dynamique ») et rejette A — **Décision

structurante majeure**, raison obligatoire : « mains déformées ». A passe à écartée (réversible).

4. Choix de la source. Elle désigne B comme média actif (rôle exclusif). *(Décision ; B reste un

Média produit, son état/rôle change — pas de copie.)*

5. Contrôle qualité. Avant toute étape coûteuse, le QC juge B : conforme (identité fidèle à la

Référence).

6. Cohérence. L'Évaluation de cohérence signale une pièce à vérifier : script — ton « fun »

vs émotion visée « douceur ». La personne assume l'écart (« clin d'œil voulu ») → Décision ; le

signal se referme. (Le système n'a rien corrigé seul — INV-2.)

7. Suite de production. Le Script est validé pour production (Décision majeure, raison

obligatoire) ; la Voix l'interprète ; B (+ une variante) est retenue-pour-livrable ; le

Montage assemble les plans (rythme réglé — action mineure, pas de Décision).

8. Retour en arrière maîtrisé. La personne change finalement le Look (« le précédent faisait trop

strict »). Comme l'aval existe, le système expose le choix garder / mettre à jour / régénérer ; elle

choisit mettre à jour — Décision, jamais d'effacement silencieux (INV-6).

9. Version + Livrable. Elle enregistre une Version (instantané) puis la retient (raison : «

meilleur compromis identité/impact ») ; un Livrable complet se constitue (média final + Légende

courte/longue + Hashtags + Paramètres + RAW). État : prêt-à-poster.

10. Publication. Effet annoncé avant ; la personne publie — seul acte irréversible. La

version publiée est figée ; le projet passe finalisé.

11. Mémoire. Des mois plus tard, dérouler l'Historique raconte tout : l'intention, les trois

candidates, pourquoi A rejetée, pourquoi B retenue, l'écart de script assumé, le changement de look et

sa raison, la version publiée. Rien n'a été effacé ; tout est explicable.

12. Capitalisation. Le Look mis à jour est promu en brique-modèle (provenance : ce projet) ;

un prochain projet pourra le réutiliser par copie — sans jamais toucher celui-ci.

Le scénario montre l'ensemble : un objet (Média produit) qui traverse ses états, des **décisions
motivées qui se propagent sans rien effacer, une mémoire** qui rend le projet relisible, une
cohérence qui éclaire sans décider, et une seule porte définitive : publier.
